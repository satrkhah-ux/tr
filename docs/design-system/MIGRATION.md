# خطة الترحيل — غير منفَّذة

المبدأ: دفعات صغيرة، كل دفعة **بلا تغيير مرئي في الفاتح** ونفس ألوان الداكن، ثم مقارنة لقطات قبل/بعد على شاشتين على الأقل، ثم نشر. أي توحيد يغيّر لوناً (مثل دمج `#d8e6e0` في `#e2ebe7`) يُفصل في دفعة مستقلة بموافقة المالك.

قاعدة الترتيب: أصناف الرموز (`border-tv-…`) تغلب `border-[#…]` على نفس العنصر؛ فإذا كان للثابت مستخدمون يضيفون لون خطأ، اكتب الأساس كـ`@utility` (مثل `tv-field`) بدل أصناف الرموز. افحص المستخدمين قبل كل دفعة بـ`grep -rn "<اسم الثابت>" src`.

## ما يحتاج قرار المالك قبل البدء
1. **تغييرات مرئية مقصودة** (خارج الخطة الصامتة): تغميق `#93aaa3` (465 موضعاً، 2.46:1)، إضافة حلقة تركيز مرئية للأزرار والحقول، تقوية حد الحقل (1.28:1)، تكبير أزرار `h-7/h-8` على الهاتف.
2. **الزر الموحَّد**: اعتماد `ui/button.tsx` (غير مستعمل) أو ثوابت أصناف.
3. **صفحات OKX** (`src/app/{wallet,trade,markets,p2p,login,signup,support}` و7 مكوّنات): حذف أم إبقاء — 578 استخداماً للونها.
4. هل يتبع نص الحقل لون الشريك `--tv-brand` في بوابة الشركاء؟ اليوم ثابت `#185045`.

## التحقق لكل دفعة
`npx tsc --noEmit -p .` ← `npx vitest run` للملفات المعنية ← بناء الإنتاج في `tv-verify` ← `grep` لملف CSS المبني للتأكد من بقاء الرموز ← مقارنة القيم المحسوبة (`getComputedStyle`) قبل/بعد في الفاتح والداكن كما في الدفعة 0.
